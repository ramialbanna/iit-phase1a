## 4a. Proposal to shorten the remaining S2 path (for Codex; not approved)
E-1, E-2 and E-3 are each "one Add on the test app with a fixed payload and read-only reconciliation" — the same harness pattern as docs/46, differing only in the pre-state they require (iD absent / iD present-ours / iD present-unrelated). Proposal: **one** plan (docs/52) and **one** harness run that sends exactly **three** Adds in a fixed order with stop-on-first-failure — (1) new iD `S2A-20261026-0002` into a key configured Editable ✗ if AppSheet permits it (E-1); (2) the same iD again, same payload (E-2, duplicate-ours); (3) the same iD with a different VIN/payload (E-3, **collision candidate**: AppSheet's response + original row unchanged; not C5 closure) — each followed by the full reconciliation and each classified independently, with database-free controls for every branch before Codex review. One review cycle and one approval instead of three. Live 3.1 is not involved; E-5/E-6/E-7 stay separate.
