# Migration 009 — expected-state tokens on every state-dependent write

Status: **local only, rev 1 — for Codex review.** Not applied to Supabase. Branch `feat/009-expected-state-writes` from `main`
at `6cf885bc017fb640f5098a081f8a05d069801d0c`. Implements owner decision F and closes the stale-write gate of
`007-stale-write-gap-report.md` (the final database gate before the Base44 production connection).

22 functions changed; 5 unchanged; the 10 read RPCs (007) are unchanged except `list_work_items`, which now returns each row's
`state_token` (deal token, or the item's own token when it has no deal) so work-item writes have a token to send.

## 2. Mechanism
Each of the 22 deployed functions keeps its exact body and is renamed `iit._<name>_unchecked` (owner-only; EXECUTE revoked
from `iit_base44` and `iit_integration`). A new public `iit.<name>(…, p_expected_state text, p_actor_base44_user_id text)`
(`SECURITY DEFINER`, owner `iit_owner`, `search_path = ''`):
1. runs `require_role(actor, role)` — the unchanged credential, `jti`, revocation, identity and staff-role checks — before
   anything about state is consulted (`resolve_work_item`, whose role is the item's, first runs the credential/identity check
   and checks the role under the lock, as 003 does);
2. refuses a missing token — `STATE_TOKEN_REQUIRED` — or a malformed one (anything but `v1:` + 32 lowercase hex) —
   `STATE_TOKEN_INVALID`; SQLSTATE 22023; omission can never bypass the check;
3. takes the row locks in the established order — Deal first (every writer does); appraisal identity → Deal → item for
   `resolve_restart`; Deal → action for `resolve_unknown_outcome` — then recomputes the token **under the locks** and refuses
   a mismatch with **`STALE_STATE`**, SQLSTATE **`PT409`** (PostgREST answers HTTP 409), `DETAIL current_state_token=<token>`
   so the UI can reload;
4. delegates to `_<name>_unchecked`, which repeats its own role check and does everything it always did: validation, locks,
   actor push/restore, history, activity, audit.

A refusal raises before the unchanged function runs: no mutation, history, activity or audit row. An unknown target id skips
the comparison and reaches the unchanged function's own `…_UNKNOWN` error. Signatures keep `p_actor_base44_user_id` last;
return types are unchanged (Base44 re-reads the token after each write — `get_deal`, a list row, or the 409's DETAIL).

**Tokens Base44 sends:** `get_deal.state_token` (and the frozen view's) for every deal-keyed write;
`list_work_items` rows' `state_token` for `resolve_work_item` / `resolve_restart`; derived consignment rows' `state_token` for
`set_consignment`; `get_unknown_outcome.state_token` for `resolve_unknown_outcome`. Token definitions are 007's
(`docs/migrations/007-contract-worksheet.md` §2.5) plus `_work_item_state_token` for an item with no deal.

## 4. Defaults recorded
| # | Default | Reason |
|---|---|---|
| E-1 | Wrap-and-rename rather than rewrite: the deployed bodies are untouched, so every authorization, actor, history and audit path is unchanged by construction | smallest reviewable change; no business logic re-typed |
| E-2 | Conflict code `STALE_STATE` (gap report §3) with SQLSTATE `PT409` → HTTP 409 via PostgREST; missing/malformed token `STATE_TOKEN_REQUIRED` / `STATE_TOKEN_INVALID` (22023 → HTTP 400) | the gap report's codes; a status the Base44 adapter can branch on |
| E-3 | Row-keyed writes (attempt, report, waiver, hold, flag, item) check the **deal** token, not only the row | gap report: the decision depends on the displayed deal context; the deal token covers those rows too |
| E-4 | Admin writes and `create_manual_deal` stay token-free (§1) | absolute commands / creation |
| E-5 | `iit_integration` receives the new signatures (and loses the old) | D-49: it stays the local-test mirror of the staff surface |
| E-6 | Return types unchanged; the new token comes from a re-read or from the 409's DETAIL | no further signature changes to the manifest |
| E-7 | `list_work_items` (007) replaced to add `state_token`; its signature and access are unchanged | work-item writes need a token Base44 can read |
