## 1. What it creates
1. **V-2** — `ALTER DEFAULT PRIVILEGES FOR ROLE iit_owner REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC` (global, no `IN SCHEMA`),
   first statement after `SET ROLE iit_owner`, before any 007 function. One `pg_default_acl` row: `iit_owner`, namespace 0,
   type `f`, `{iit_owner=X/iit_owner}`. Every function still has its own `REVOKE ALL … FROM PUBLIC`. The per-schema no-op
   statements in 001/006 are left as they are.
2. **`iit.read_access_audit`** — identifier-minimized, append-only, no privilege for any role but the owner (worksheet §2.4).
   Shared contract for later get_report-style functions and available to 008 (its Q4 is re-evaluated against this table).
3. **Ten read RPCs**, granted to `iit_base44` only (manifest 27 → 37): `get_my_profile(text)`, `get_deal(uuid,int,text)`,
   `list_work_items(text,text,int,text,text)` (data_entry, auditor, audit_lead — never admin), `list_audit_queue(text,int,text,text)`, `list_unknown_outcomes(int,text,text)`,
   `get_unknown_outcome(uuid,text)`, `get_dashboard_summary(text)`, `list_staff(text,boolean,int,text,text)`,
   `list_source_channels(int,text,text)`, `search_deals(text,text,int,text,text)`.
4. **Twenty internal helpers** (`iit._read_ctx`, `_require_read`, paging/cursor/envelope helpers, state tokens, projections,
   eligibility, visibility, `_audit_read`), owner-only.

Not changed: every 001–006 function, table, grant and membership (fresh-install catalog diff: additions only); the 27 write
signatures; `require_role`; `authorize_report_access`; `iit_integration`'s manifest; D-36/D-40 (created empty, untouched).
Not here: `get_report` (deferred), expected-state enforcement in writes (gap report — pre-connection gate), PostgREST
exposure, credentials, Base44 connection.
