# Migration 001 — foundation (schema `iit`)

Status: **local only, rev 2** (Codex findings 1–6 applied). Applied and tested on a fresh local Postgres 16 (`supabase/tests/run_local.sh` → `ALL 001 TESTS PASS`, 19 check blocks). Not applied to Supabase. For Codex review.

## 0. Rev 2 — Codex 001 findings and what changed
| # | Finding | Change | Control |
|---|---|---|---|
| 1 | Lifetime `UNIQUE(appraisal_ref_id, body_hash)` blocked A→B→A | Uniqueness removed; a BEFORE INSERT trigger rejects only a hash equal to the **latest** observation of that appraisal (`seq` column gives insertion order) | T12f consecutive duplicate rejected; T12g A→B→A stored (3 rows) |
| 2 | Released version could be reassigned while superseding | Guard requires `to_jsonb(NEW) - 'status' = to_jsonb(OLD) - 'status'` and `NEW.status='superseded'` | T10e deal_id, T10f version_no, T10g opened_at, T10h released_by all rejected; status-only transition allowed |
| 3 | Staff-access changes lacked durable history; composite-key tables uncovered | `history_trigger` generalised: `record_key` text (PK columns from `TG_ARGV[0]`, `a|b` for composites), `op` I/U/**D** with before image, `record_id` kept when a uuid `id` exists. Attached to `staff_identities`, `user_roles` (DELETE recorded), `external_user_map`, `roles`, `organization_roles`, `source_channels`, `required_fact_rules`, `material_fields`, `system_settings`, `shift_calendar`, `json_schemas`, `deal_versions`, `external_references`. `deactivate_staff` writes an activity event. | T7b/T7d identity history with before/after + attribution; T7e/T7f revocation recorded (function and direct); **T18 inventory**: every table in `iit` has `zz_history` or `zz_append_only` — no exclusions |
| 4 | Group-name checks ≠ allowlisting; undecided bodies admitted anything | New `iit.json_schemas` (per-body field-level allowlist, itself history-covered) + recursive `json_matches_schema` + `enforce_json` BEFORE trigger. Seeded: `vauto_observation` with the fields the design names in §7 (nested, leaf-strict); `source_observation_31`, `deal_version_snapshot` **empty = fail closed** (only `{}` passes) until D-8 / the release slice; `activity_event_detail` = exactly the keys this slice writes. `record_history.before/after` are `to_jsonb(row)` of tables that hold only allowlisted columns, so they are allowlisted by construction (no raw payload column exists anywhere in `iit`). | T12a top-level, T12b **nested**, T12e scalar-for-structure rejected; T12x-a non-empty 3.1 body rejected; T10i non-empty snapshot rejected; T19 stray activity key rejected |
| 5 | `current_observation_id` could point at another record's observation | Composite FK `(current_observation_id, id) → source_observations(id, source_record_id)` | T12x-b cross-record rejected, own accepted |
| 6 | `deals.consignment_id` could point at another deal's consignment | Composite FK `(consignment_id, id) → consignments(id, deal_id)` | T12y-a cross-deal rejected, own accepted |

## 3. Dependencies on excluded bridge objects (§5.8) — named, not stubbed
- `release_deal()` (future slice) is specified to "queue the initial `add_31_row` delivery on first release". With the bridge deferred it will **not** do that; the slice that adds `release_deal` must state this and provide no placeholder.
- `source_records.created_via = 'bridge'` and `work_items.kind IN ('id_collision','delivery_failed_manual','vin_validation_rejected','duplicate_row')` are vocabulary only; nothing creates them.
- `source_records.legacy_iid` is "NULL until known"; with no bridge it is set only by cutover/manual paths (future slice).
